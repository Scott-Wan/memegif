# 视频转 GIF 表情包小工具 —— 设计文档

- 日期：2026-05-31
- 状态：待用户评审
- 项目位置：`F:\gifmaker`

## 1. 目标与定位

做一个**小型实验性**的桌面工具：把视频拖进窗口，可视化地截取一小段，转换成**循环播放、尽量清晰、体积达标**的 GIF，用于发表情包。

主用途是 **QQ 表情**，同时顺手支持**微信表情**（仅参数预设不同，代码几乎一致）。

### 成功标准

- 能把视频拖入窗口（或点击选择），在窗口里看到画面并可视化选起止点。
- 选好后一键转换，输出的 GIF：循环播放、画面尽量清晰、体积稳定落在所选预设的上限内。
- 转换过程无需手动调任何 ffmpeg 参数；超限时自动回退到达标。

## 2. 技术形态与架构

**内核：Python + ffmpeg。窗口：pywebview（原生桌面窗口内渲染 HTML 前端）。**

选 pywebview 的原因：可视化选段需要视频播放 + 拖动时间轴 + 实时预览，HTML5 `<video>` 标签原生支持播放与进度控制，做双滑块选段最省力、体验最好；pywebview 把网页包成一个独立桌面窗口，看起来就是个桌面程序，体积小，后续打包 exe 也方便。机器已确认自带 WebView2 运行时，无需额外安装。

## 3. 功能详述

### 3.1 导入视频

- 主路径：把视频文件拖进窗口。
- **兜底路径：一个「选择文件」按钮。** 原因见第 8 节技术风险——pywebview 内 HTML5 拖拽拿本地文件**绝对路径**不一定可靠，按钮用 pywebview 原生文件对话框，保证一定能拿到路径。
- 导入后把视频喂给 `<video>` 预览（通过本地文件 URL 或后端提供的临时可访问地址）。

### 3.2 可视化选段

- `<video>` 可播放/暂停/拖动。
- 时间轴下方一条**双滑块**控件：左滑块=起始秒，右滑块=结束秒，实时显示选中区间（如 `3.0s – 8.0s`）和时长。
- 拖动滑块时，`<video>` 跳到对应时间点预览那一帧，方便对齐。
- 默认起止 = 整段视频；用户可收窄。

### 3.3 预设（目标体积）

两个预设按钮，点哪个就用哪套参数转换：

| 预设 | 体积上限 | 最大边 | 起始帧率 | 取向 |
|------|---------|-------|---------|------|
| **QQ**（默认） | ≤ 5 MB | 480 px | 15 fps | 尽量清晰 |
| **微信表情** | ≤ 1 MB | 300 px | 12 fps | 保证能加进表情面板 |

「最大边」= 宽高里较长的一边缩到该值，另一边按比例缩放，保持原始宽高比。

### 3.4 转换算法（清晰 + 体积达标）

ffmpeg 没有「目标文件大小」参数，采用**两步调色板 + 自动回退**：

1. **生成专属调色板**：`ffmpeg ... palettegen`（针对选中片段生成最优 256 色调色板，这是 GIF 清晰的关键）。
2. **应用调色板转 GIF**：`ffmpeg ... paletteuse`，按当前「最大边 + 帧率」输出，默认 `-loop 0`（无限循环）。
3. **量体积**：转完测文件大小。若 ≤ 上限 → 完成。
4. **超限则回退**：按梯度逐步降级再转，**先降分辨率、再降帧率**，最多约 4–5 轮，直到达标或触底（触底仍超限则输出当前最小结果并提示）。
   - 回退梯度示例（QQ）：480→400→320→256 px；帧率 15→12→10 fps。
   - 调色板可在每轮复用或重算（实现时取简单稳定的做法）。

### 3.5 输出

- 默认存到**源视频同目录**，文件名加预设后缀：`原名_qq.gif` / `原名_wechat.gif`。
- 转换完成后状态栏显示：输出路径 + 最终体积 + 实际尺寸/帧率（便于判断清晰度）。

## 6. 错误处理

- 拖入/选择的不是视频或 ffmpeg 无法识别 → 状态栏明确报错，不崩溃。
- 起止时间非法（起 ≥ 止、超出时长）→ 前端拦截并提示。
- ffmpeg 进程失败（非零退出）→ 捕获 stderr，状态栏给出可读原因。
- 体积回退触底仍超限 → 输出当前最小结果，提示「已尽力压缩到 X MB，仍超出上限，建议再缩短片段」。

## 7. 测试策略

- `converter.py` 设计成可独立调用的函数（输入：视频路径、起止、预设；输出：gif 路径、体积、实际参数），便于单测。
- `tests\test_converter.py` 用 `assets\sample.mp4`：
  - 转 QQ 预设 → 断言体积 ≤ 5MB、文件存在、是 GIF（含循环标志）。
  - 转微信预设 → 断言体积 ≤ 1MB、最大边 ≤ 300px。
  - 构造一段较长/较大的输入 → 验证回退逻辑确实触发且最终达标。
- 前端选段交互以手动验收为主（实验项目，不做端到端自动化）。

## 8. 已知技术风险

- **pywebview 内 HTML5 拖拽拿本地文件绝对路径**：各平台支持不一致，可能拿不到真实路径。**对策**：以原生「选择文件」按钮为可靠主入口，拖拽作为增强（能拿到就用，拿不到就引导点按钮）。
- **`<video>` 预览本地文件**：需要让前端能访问本地视频。对策：用 pywebview 暴露本地文件 URL，或后端起一个极简本地静态服务/临时拷贝提供预览。实现时选最简单可行的一种。

## 9. 视觉设计与美术风格

整体走 **深色主题 + 暖橙色强调** 的现代简洁风格，参考图 `C:\Users\PC\Pictures\QQ20260531-081145.jpg`（Claude Code 配色）。**配色与图形气质照此参考，布局由实现自定。**

### 配色（暂定，可在实现时微调）

| 用途 | 颜色 | 说明 |
|------|------|------|
| 主背景 | `#1C1B1A` 系 | 近黑的暖灰，不是纯黑 |
| 次级面板/卡片 | `#262422` 系 | 比主背景略浅，用于分区 |
| 主强调色 | `#D97757` 系（陶土/珊瑚橙） | 按钮、滑块、高亮、logo |
| 强调色悬停 | 比主强调略亮的橙 | 交互反馈 |
| 主文字 | `#ECECEC` 系 | 高对比浅色 |
| 次要文字 | `#9B9B9B` 系 | 提示、说明 |
| 边框/分隔 | 低对比深灰 | 柔和不抢眼 |

### 风格要点

- 圆角元素（按钮、卡片、`<video>` 容器、滑块手柄）。
- 橙色作为唯一强调色，克制使用，集中在可交互/状态元素上。
- 拖入区在空闲时是虚线圆角框；拖拽悬停时边框与背景泛橙提示「可释放」。
- 双滑块时间轴：轨道为深灰，选中区间与手柄为橙色。
- 状态栏用颜色区分：进行中（橙）、成功（绿）、错误（红），其余浅灰。
- 图标用**内联 SVG**，零依赖；字体用系统默认无衬线，不引入外部字体。

### 实现约束

- 纯手写 CSS 实现，不引入 UI 框架/图标库/外部字体（保持零额外依赖、不污染环境）。
- 如需更精致的动效或图标库（会引入额外依赖），先与用户讨论再加。
